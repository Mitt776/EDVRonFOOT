# Proposal

## Why

20.10.2026 игра обновилась до сборки `2026.10.13.334473`. Ключ `native_vr_on_foot` знает адрес байта кинотеатра
(`0x5E82B3E`) только для сборки 332841, поэтому на новой сборке он ничего не делает и на ногах снова кинотеатр.
В новом exe тот же байт нашёлся по коду вокруг него: теперь он лежит по адресу `0x5E85B8A`, читает его по-прежнему одно
место, `0x288A139`, а узор кода вокруг этого места встречается в exe ровно один раз. Если наш код будет находить байт
по этому узору при каждом запуске игры, VR на ногах заработает на 334473 и, скорее всего, переживёт следующие
обновления, пока Frontier не перепишут это место. Обновления приходят без предупреждения: сегодняшнее ещё и удалило
EDVR из папки игры.

## What Changes

- Шлемовая камера на ногах (байт кинотеатра) больше не привязана к сборке 332841. При запуске EDVR ищет в коде игры
  узор «вызов проверки вида от первого лица, затем сравнение байта». Байт берётся из этого узора и трогается, только если:
  - узор найден ровно один раз;
  - байт лежит внутри образа игры, в разделе данных, доступном для записи;
  - в байте стоит 1, как в exe игры.
  Иначе ничего не пишется, а в лог идёт одна строка с причиной. Правило «писать только 1 → 0 и обратно только наш
  0 → 1» не меняется.
- Строки лога называют найденный адрес и сборку игры, а не фиксированный `0x5E82B3E`. На 334473 должно получиться
  `EliteDangerous64.exe+0x5E85B8A`.
- Удержание-страховка (подмена кинотеатра в источнике режима) и зонд `native_vr_probe` остаются только для сборки 332841.
  На другой сборке они честно пишут, что не установлены, и при этом не сообщают, будто «игра оставляет кинотеатр»,
  если байт найден.
- Новая сборка `v0.19.1-edvronfoot.8`. Её надо поставить в игру заново, потому что обновление удалило EDVR. Нужно
  вернуть и живой `edvr.ini` из копии. Скрипт `edvronfoot_game.ps1 -Action Install` без слепка официальной версии
  откажется работать, а слепок обновление тоже удалило. Поэтому ставим штатным `tools\install_edvr.py`. Откат на
  официальную версию недоступен, пока слепка нет; так и записываем.

**Как проверить руками (Дима).** Один короткий полёт на .8:
1. Запуск игры. VR в корабле работает как раньше.
2. Выход на ноги. Картинка в настоящем стерео, голова отслеживается, глаза сводятся, как на .6 и .7.
3. Возврат в корабль. VR в корабле как обычно.
4. Выход из игры.

Лог я проверю сам: там должны быть строки «найден байт кинотеатра по узору ... +0x5E85B8A ... 1 -> 0». Если
сложится, в этом же полёте снимем разведку интерфейса из заявки `native-vr-on-foot-ui-recon`: на ногах шесть
нажатий NumLock. Это делается отдельным шагом той заявки и в эту заявку не входит.

## Capabilities

### New Capabilities

- нет

### Modified Capabilities

- `native-vr-on-foot`: требование «Только известный билд» меняется. Шлемовая камера на ногах работает на любой сборке,
  где байт кинотеатра найден по узору кода и проверен. Удержание стерео остаётся только для сборки 332841. Добавляется
  требование о том, как ищется и проверяется байт.

## Impact

- Код:
  - `edvr/src/d3d11/native_vr_probe_core.h`: поиск узора и проверки как чистые функции, тексты строк;
  - `edvr/src/d3d11/native_vr_probe.cpp`: поиск при первом запуске, отдельно от проверки сборки для зонда, тексты
    строк про удержание;
  - стенд `edvr/tools/native_vr_probe_test`: новая часть с синтетическими буферами.
- Сборка `v0.19.1-edvronfoot.8`, тег. Установка в игру, восстановление живого `edvr.ini`.
- Документы: README `edvr/README_EDVRONFOOT.md` (раздел про `native_vr_on_foot`), исследование
  `docs/research/native-vr-on-foot.md` (`## Status`, итог полёта).
- Зонд `native_vr_probe` и Explorer Cam остаются привязаны к 332841, их перенос в эту заявку не входит. Что ещё в самом
  EDVR сломало обновление (подмена разрешения экрана, размеры панелей), покажет лог полёта. Если что-то сломалось,
  это записывается отдельно.
