# Design: on-foot-marker-pose

## Context

Мотивация — в proposal.md. Что есть сейчас:

- Рантайм EDVR отвечает на запрос игры «где голова сейчас» (`GetDeviceToAbsoluteTrackingPose` с предсказанием около 0
  из образа игры, сейчас с возвратом `exe+0x4E3921`) позой на время **показ последнего кадра + один такт**
  (`head_pose_time.h` `answerTime`, `native_runtime_host.h` `poseTargetFor`). Это решение терренной арки 10.10.
- Та же арифметика даёт «позу для игровой логики» в массиве WaitGetPoses (`native_runtime_host.h`, `gameplayTime` через
  `nextPredictionTime`).
- На ногах включён режим Turbo (`fix.weapon_stability`): игре сразу отдаётся синтезированное время показа (последнее
  настоящее + 1–2 такта, `frame_boundary.h` `synthesizedTime`), а настоящее ожидание идёт параллельно. При 45 к/с
  соседние кадры, которые рисует игра, отстоят на два такта.
- Канал кадра d3d11 → рантайм (`EdvrNativeFrameOutput`, `common/native_frame.h`, сейчас версия 8) уже несёт флаг
  «на ногах» в виде `deferredPacing`; так же сюда добавляется новый флаг.
- Диагностика `pose gap:` (`pose_gap.h`) раз в 60 с пишет по каждому вызывающему потоку расхождение ответа с нарисованной
  позой следующего кадра (`angle-to-drawn`).

## Goals / Non-Goals

**Goals:**
- Один полёт с переключением на лету отвечает: прилипает ли подпись к NPC, если ответ «сейчас» идёт на реальный шаг кадров.
- В ship-режиме, в кинотеатре и при `next` поведение побайтно прежнее.

**Non-Goals:**
- Не трогаем правку камеры меток PostGUI (`on_foot_markers.cpp`), прицел головой и Turbo.
- Не ищем, какой именно код игры ставит подсказки (статика) — сначала проверяем догадку в шлеме.
- Субтитры отдельно не чиним; если они рисуются тем же слоем, это покажет тот же полёт.

## Decisions

1. **Шаг кадров = медиана последних 16 разностей времени показа, отданного игре.** Берём `frame.predictedDisplayTime`
   после `admitFrame` (то, с чем игра реально рисует), разность с предыдущим кадром, медиану по 16, ограничение снизу одним
   тактом, сверху `min(4 такта, 50 мс)`. Медиана, а не последнее значение: при смеси 1- и 2-тактных кадров (54 к/с) одиночный
   скачок не должен дёргать позу. *Альтернативы:* «всегда два такта на ногах» — неверно при 54–90 к/с; предсказание по
   реальным ожиданиям OpenXR — сложнее и не то время, с которым рисует игра.
2. **Режим решает d3d11-сторона, рантайм только исполняет.** В `native_frame.cpp` флаг `markerPoseFrame` =
   ключ `frame` && журнал знает, что на ногах (как у `deferredPacing`). Новое поле — в конец `EdvrNativeFrameOutput`,
   версия 9; старая сторона без поля = `next`. *Альтернатива:* свой ini у рантайма (`edvr_openxr.ini`) — нет на лету и нет
   F8.
3. **Поза для игровой логики в WaitGetPoses меняется вместе с ответом «сейчас».** Подсказки могут брать любую из двух поз;
   один полёт должен покрыть обе. Флаг для неё берётся с прошлого кадра (поза считается до `features.begin` этого кадра) —
   на переключении это один кадр запаздывания, неважно.
4. **Свежесть кэша при `frame`:** допуск «кадр не старше» = измеренный шаг (с тем же потолком 50 мс), а не такт: иначе при
   45 к/с вызовы между кадрами чаще падали бы в «сейчас + предсказание».
5. **Ключ на странице Experimental, не On foot.** Спека `on-foot-settings` требует на On foot ровно шесть строк; временный
   ключ туда не кладём, чтобы не менять её ради зонда. Цена: Диме нужно включить Developer mode.
6. **Строки лога.** `marker pose: next|frame (<причина>)` на каждой смене действующего режима; раз в 30 с при `frame`:
   `marker pose: frame, step p50 X ms max Y ms, answered N`. `pose gap:` получает в конец ` mode next|frame`, окно
   закрывается на смене режима. `tools/edvr_log.py --tally pose` учится полю и делит таблицу по режиму; self-test — новые
   образцы строк.

## Risks / Trade-offs

- [`angle-to-drawn` при `frame` падает почти по построению: ответ целится в то же время, что следующий кадр] → лог
  подтверждает только, что режим действует; доказательство — глаза Димы (подпись прилипла или нет). Так и записать в итоги.
- [Подсказки ставятся не по этим позам] → подпись сползает и при `frame`; это `ruled out` в доклад, ключ удаляется.
- [Отсечение ландшафта на планете берёт ту же позу] → при полной частоте ничего не меняется; при 45 к/с время ближе к
  кадру. Короткая проверка краёв на планете в полёте.
- [Шаг считается на синтезированных временах Turbo, а они ограничены 1–2 тактами] → при 45 к/с шаг ровно два такта, при
  более медленной игре потолок 4 такта / 50 мс; ниже 30 к/с на станции не бывает.
- [ABI канала кадра] → поле в конце, версия +1, проверка размера как у прошлых версий; стенды `openxr_native_test`.

## Migration Plan

Сборка → установка `install_edvr.py` → полёт → решение Димы. Откат — ключ `next` (по умолчанию) или прошлая сборка.
После полёта: победитель становится поведением, ключ `experimental.native_vr_on_foot_marker_pose` удаляется (только
спросив Диму, с цитатой ключа), строки зонда сокращаются до одной строки о включении.
