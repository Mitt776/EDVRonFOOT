# Design

## Context

Зачем и что — в `proposal.md`. Здесь только то, как устроен код сейчас и что из этого следует.

- Прицел головой и зонд живут в одном файле `edvr\src\d3d11\head_aim_probe.cpp`: одни и те же хуки (два геттера
  углов и геттер матрицы глаза), одна защёлка (`head_aim_signal.h`), один шаг кадра. Зонд добавлял поверх этого свои
  сдвиги (`hap::Mode`, `Ramp`, `Shift`, качание), строку `watch`, сводку и ключ компенсации. Фиче нужны из «чистой
  половины» зонда (`head_aim_probe_core.h`): проверка байтов и строки `hooked`/`inert`, ворота «на ногах»
  (`Gate`, `onFootFlag`), перепись HMC и опознание игрока (`Census`, `CameraCheck`, `identify`, `formatIdentity`).
- `head_aim_core.h` держит выборы, которые больше не нужны: `Key::Raw`, `PitchComp::{Minus,Off}`, `Sync::Latch`,
  `StickComp::Off`, разбор `pitch_offset`, и строку ключей со всеми пятью значениями.
- Канал d3d11 → рантайм (`native_frame.h`) версии 7 и 8: поля `headAimYawRad`, `headAimProbe`, `headAimPitchRad`,
  `headAimFeature`. Правило «DLL копируют по одной» запрещает менять раскладку.
- F8 и контракт конфига собираются из строк `# ui:` в `edvr\edvr.ini` (`gen_settings_schema.py` →
  `build\gen\menu_schema.inc`, `config_contract_gen.h`), так что пункт уходит из F8 вместе с блоком в ini.
- Ширина HUD: `on_foot_hud.cpp:282` читает `native_vr_on_foot_hud_size` через `ofh::` разбор ширины
  (`on_foot_hud_core.h:328`, по умолчанию `kWidthDefault` = 85); меню считаются в долях от неё.

## Goals / Non-Goals

**Goals:**
- Поведение `.46` при ключах по умолчанию совпадает с облетанным `.41`–`.45` при `head_aim=on`, плюс прицел включён
  без F8.
- В коде не остаётся путей, которые выбирались только удалёнными ключами.

**Non-Goals:**
- Не трогаем рантайм (`src\openxr\`) и раскладку канала: `openvr_api.dll` собирается заново, но поведение у неё то же.
- Не меняем фильтр, предел ±90°, ворота меню/фокуса, ведущий глаз и ноль положения.
- `on-foot-hud-lazy-yaw` остаётся на паузе.

## Decisions

1. **Файлы: `head_aim_probe.cpp/.h` → `head_aim.cpp/.h` (`git mv`), `head_aim_probe_core.h` удаляется.** Общие
   части (проверка байтов и строки хуков, ворота, перепись, опознание) переезжают в `head_aim_core.h` в пространство
   `ha::`, префикс строк `head aim probe:` → `head aim:`. Вызовы в `device_hook.cpp`: `headAimInstall`,
   `headAimFrameBoundary`. *Другой вариант:* оставить имя файла и вырезать только зонд — меньше правок, но имя
   «probe» у постоянной фичи будет путать в следующих сессиях. Переименование дешёвое, `git mv` сохраняет историю.
2. **Канал не меняем.** Прокси всегда пишет `headAimProbe = 0`. Версия 7 без 8 (старый рантайм) значит «фича не
   включается», как сейчас (`reason channel`). Комментарии в `native_frame.h` и рантайме, где есть слово «probe»,
   остаются историей раскладки, их не правим. *Другой вариант:* убрать поле и поднять версию — ломает правило DLL
   и ничего не даёт.
3. **Выбранные значения — константы, пути выбора удаляются.** Поворот позы по наклону = `added` (бывший `plus`);
   такт = выбор `camera` (`chooseAnswer` без режима); поправка по наклону = вариант `stick_comp=on`; поправка ствола
   `kPitchOffsetDeg = 10`. Строка такта остаётся без поля режима: она дешёвая и сразу покажет, если обновление игры
   поменяет порядок камеры и защёлки.
4. **Ключ фичи:** `off` → выкл; пустое или нет ключа → `on` молча; `on` → `on`; любое другое (в том числе старое
   `raw`) → `on` с одной строкой `not understood, reads on`. Строка ключа: `head aim: key=on|off`. *Почему `on` для
   неизвестного:* значение по умолчанию теперь `on`, а опечатка не должна молча выключать фичу, которой человек хотел.
5. **Ширина HUD — константа 85** (`ofh::kWidthDefault`); разбор ширины и его проверки на стенде уходят. Строка
   ключей HUD называет только крепление.
6. **Оставшиеся строки в живом ini.** Код удалённые ключи не читает, поэтому строки ничего не меняют. Живой
   `edvr.ini` игры чистим через Edit (как в `.45`). Перед этим проверить, не пишет ли загрузчик конфига
   предупреждение на неизвестный ключ и не возвращает ли установщик блоки из старой базы: смотреть `--dry-run`.
7. **Стенды.** `tools\head_aim_probe_test\` и гейт `:rig_head_aim_probe_test` удаляются. Проверки опознания,
   ворот и строк хуков переносятся в `tools\head_aim_test\` (без проверок сдвигов зонда). Из `head_aim_test`
   уходят проверки `raw`, `minus`/`off`, `latch`, `stick_comp=off`, разбора угла; добавляются проверки разбора ключа
   по решению 4. Стенд HUD теряет проверки разбора ширины. `build.bat` правится так, чтобы он остался CRLF.

## Risks / Trade-offs

- [У кого ключа нет, прицел включится сам] → это решение Димы; выключить — один пункт F8 `off`. В описании ключа в
  ini прямо сказано, что он включён по умолчанию.
- [Переезд опознания игрока сломает его, и NPC начнут крутиться или фича не включится] → проверки опознания
  переезжают на стенд вместе с кодом; в полёте смотреть строку `head aim: player identified` и станцию с NPC.
- [Ширину HUD 26.10 решили оставить, сейчас — убрать] → решение Димы 02.11 новее; если ширина понадобится,
  ключ возвращается из git (`v0.19.1-edvronfoot.45`).
- [Убрана правка, которой подбиралась поправка 10°: у другой посадки/шлема она может быть не та] → Дима выбрал
  зашить; вернуть ключ можно из `.45`.
- [`build.bat` сохранится с LF и cmd перестанет находить метки] → проверить концы строк после правки.

## Migration Plan

1. Сборка `.46` (`build.bat --jobs 8` по абсолютному пути, все гейты), коммит, тег, `--dll-only`, установка
   `install_edvr.py --target steam`, `--verify-only`.
2. Живой `edvr.ini` игры: убрать строки удалённых ключей Edit-ом, `native_vr_on_foot_head_aim` поставить `on` или
   убрать (если там `raw`, заменить на `on`).
3. Полёт: см. `tasks.md`, группа полёта.
4. Откат: переустановить `.45` (`git checkout v0.19.1-edvronfoot.45` → сборка → установка), ini не трогать — лишние
   для `.45` строки там не мешают, а недостающие читаются по умолчанию.
