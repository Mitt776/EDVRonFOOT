# Design

## Context

Мотивация — `proposal.md`. Как устроено сейчас:

- Строки меню F8 и окна установщика не пишутся руками: их делает генератор `edvr/tools/gen_settings_schema.py` из
  пометок `# ui:` в шаблоне `edvr/edvr.ini` и из ключей, которые читает код.
- Страница строки задаётся токеном `| menu <page>` (есть `fixes`, `performance`, `explorer_cam`). Токен разрешён
  только для `[fix]` и `[menu]` (`MENU_ROW_SECTIONS`); такие строки — для всех (tier Fix).
- Все ключи `[advanced]` / `[experimental]`, которые читает код, генератор кладёт в tier Advanced / Experimental. Меню
  показывает их только с Developer mode (`menu.cpp`, `buildPages()`).
- Установщик показывает только ключи из `EXPOSED_SECTIONS = ('fix',)`. Сам он читает и пишет ключ по полному имени
  `section.key` (`settings.cpp`), секция ему не важна. Заголовок раздела в окне — группа из `edvr.ini`; у пяти ключей
  это «Native VR on foot (EDVRonFOOT)».

## Goals / Non-Goals

**Goals:**
- Пять ключей на ногах видны всем: страница On foot в F8 и раздел в установщике.
- Ни один файл игрока не надо переносить.
- Ошибка в пометках ловится сборкой, а не в шлеме.

**Non-Goals:**
- Новые настройки, смена значений по умолчанию, смена поведения на ногах.
- Перенос других `[experimental]`-ключей на видные страницы.

## Decisions

1. **Ключи остаются в `[experimental]`, страницу даёт токен `menu on_foot`.**
   - В строке `# ui:` каждого из пяти ключей появляется `| menu on_foot`.
   - Генератор разрешает этот токен у `[experimental]`-ключа, но только с этой страницей. Строка становится tier Fix
     на странице `on_foot`, и в перечень Experimental она не попадает.
   - Другой токен `menu` у `[experimental]` по-прежнему ошибка сборки, как сейчас.
   - Отвергнуто: перенести ключи в `[fix]` (`fix.native_vr_on_foot*`). У установщика есть механизм переезда
     (`kMovedSettings`), но код DLL читает `experimental.native_vr_on_foot*` в ~20 местах, а у игроков 0.1.x старое
     имя в файле. Получились бы большая правка, риск потерять выбор игрока при переезде и ни одного выигрыша для
     игрока.
   - Отвергнуто: новая секция `[on_foot]`. Минусы те же, плюс новая секция во всех проверках генератора.
2. **В установщике — по тому же токену.** Ключ попадает в окно установщика, если он из `EXPOSED_SECTIONS` или если
   это `[experimental]`-ключ с `menu on_foot`. Заголовок раздела берётся из группы `edvr.ini`, отдельного кода нет.
3. **Страница в меню.** В `buildPages()` после Explorer Cam (до Hotkeys) появляется блок
   `p.name = "On foot"; addSettingRows(p, MenuTier::Fix, "on_foot", false);`, как у Explorer Cam. `MENU_PAGES`
   получает `on_foot`.
   - Порядок строк — порядок ключей в `edvr.ini`: Native VR on foot, interface, aiming eye, head aim, aim dot.
   - Полоска страниц станет на одну шире. С Developer mode она уже была 10 страниц и умещалась после правки ширины
     (комментарий у `menu.cpp:1929`). Ширину проверим в полёте.
4. **Проверки генератора (`--self-test`).** Новые случаи:
   - `[experimental]`-ключ с `menu on_foot` даёт строку `MenuTier::Fix, "on_foot"` и попадает в `kSettings`;
   - тот же ключ без токена остаётся Experimental и в `kSettings` не попадает;
   - `[experimental]`-ключ с `menu fixes` — ошибка.

   Сборка гоняет самопроверки, поэтому ошибка не пройдёт.

## Risks / Trade-offs

- [Секция `[experimental]` в названии видна в установщике (поиск, адрес ключа)] → для игрока это просто адрес. Слово
  «experimental» в файле не страшно: строки на странице On foot выглядят как обычные.
- [Полоска страниц F8 не влезет по ширине] → проверка в полёте. Если не влезет, название короче или правка ширины,
  как в прошлый раз.
- [Установщик при «Keep the settings I have changed» затрёт выбор в `[experimental]`] → тот же путь, что для `[fix]`
  (ключ по полному имени). Полёт проверяет это явно: значение, изменённое до установки, должно пережить установку.

## Migration Plan

Переноса нет: имена и секция ключей прежние. Откат — вернуть DLL и установщик предыдущей версии. Файл `edvr.ini` с
токенами старая версия прочтёт как обычно: токен — это комментарий.
