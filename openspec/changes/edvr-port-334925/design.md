## Goals / Non-Goals

**Goals:**
- игра `334925` запускается с нашей сборкой, дверца ставится, VR идёт через EDVR;
- профиль в DLL и в установщике один и тот же и не слабее старого;
- зонд HUD ставится на `334925` со всеми точками, и его адреса данных указывают на те же объекты игры, что в `334473`.

**Non-Goals:**
- узоры вместо привязки к ревизии; две ревизии сразу; части, привязанные к `332841`.

## Decisions

### 1. Дверца — тем же способом и с тем же стоп-правилом
Профиль заменяется на месте (`kProfileId` → `elite-odyssey-ed5a8f8c-libovr-r1`). Отпечаток блока вносится, только если
из новых байт восстановлен отпечаток `334473`, а длина блока равна длине функции по `.pdata`, где блок — целая функция.
Если хотя бы один из 11 блоков не доказан — стоп, разбор функции дизассемблером и вопрос Диме, в код не идём.
Байтовые точки, прямые вызовы, указатели таблиц и ячейка `LoadLibraryW` проверяются по новому exe так же, как в
прошлый раз (точки — по байтам, вызовы — по целям, указатели — по таблице перемещений, ячейка — по таблице импорта).

### 2. Зонд HUD: точки по байтам начала, данные — по ссылкам
- Метка `kExpectedTimestamp` → `0x6ADA8048`, SizeOfImage — проверить (ожидается тот же).
- 6 точек: новый адрес — единственное место 16 байт начала из `kPointPrologue` рядом со старым (разведка нашла их).
  Байты начала не меняются.
- Таблица методов узла, таблица методов `_HUD`, таблица сборщиков: новый адрес подтверждается двумя независимыми
  признаками по новому exe — например, указатели таблицы методов на перенесённые функции (по таблице перемещений), и
  инструкции в перенесённых функциях, которые ссылаются на адрес (`lea`/`mov` через rip). Если данные не сдвинулись
  (разделы начинаются там же), это тоже должно быть доказано, а не предположено. Где признаков меньше двух — байты из
  проекта Ghidra `ED334473` для сравнения.
- Смещения полей объектов не меняются, если байты начала функций, которые их читают, совпали; там, где зонд читает поле
  глубже, чем 16 байт начала, — сверить инструкцию в новом exe.

### 3. Тексты и спеки
Строки лога о билде («not build 334473») и комментарии — на `334925`. Стенды берут адреса из констант.

### 4. Версия `.23`
Тег `v0.19.1-edvronfoot.23`; `.22` на `334925` не стартует.

## Risks / Trade-offs

- [Функция похожа, но не та] → доказательство восстановлением старого хэша; без него в код не идём.
- [Адрес данных указывает не туда] → два признака; ошибка зонда видна в логе (узел не найден), игру не роняет — чтение
  памяти в зонде под защитой.
- [Есть ещё части, привязанные к `334473`] → grep по `src` на метку `0x6ACD513D`, хэш `6891f70a` и адреса; найденное —
  в отчёт, без молчаливого расширения.

## Migration Plan

Доказательство → правка → стенды → полная сборка → коммит, тег `.23`, `--dll-only` → установка при закрытой игре →
запуск Димой, затем прогулка `.22` на `.23`. Откат: `install_edvr.py --suspend`.
