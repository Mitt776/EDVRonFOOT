# Design

## Context

- Официальный EDVR (github.com/characterecho-sean/edvr-unofficial-patch, MIT) написан на C++. Собирается `build.bat`:
  нужны Visual Studio 2022 с C++ (есть на машине) и Python с пакетами numpy и Pillow (**Python на машине нет**,
  только заглушки Microsoft Store). Загрузчик OpenXR скачивает `tools\fetch_openxr_loader.py`, SDK DLSS — `tools\fetch_ngx.py`.
  Установленный сейчас EDVR v0.19.1 собран с DLSS (в логе `dlss="k"`).
- В EDVR уже есть всё для перехвата функций игры: `src/common/code_hook.*` (перехват первой инструкции функции,
  отказ при незнакомом прологе) и образец использования в `src/d3d11/explorer_cam.cpp`. Там же проверка билда по
  PE TimeDateStamp + SizeOfImage и сверка байтов пролога перед установкой.
- Точки наблюдения (билд 332841, подробности в `docs/research/native-vr-on-foot.md`):

| Точка | RVA | Первые байты |
|---|---|---|
| Execute `SetIdentStereoRenderModeActivity` | `0x283AFB0` | `40 53 48 83 EC 20` (push rbx; sub rsp,20h) |
| `CinemaPipelineFeature` Activate | `0x28A9690` | `40 53 48 83 EC 20` |
| `CinemaPipelineFeature` Deactivate | `0x28AB150` | `40 53 48 83 EC 20` |

  Метки exe: TimeDateStamp `0x6A989634`, SizeOfImage `0x6409000`.

## Goals / Non-Goals

**Goals:**
- Наша сборка EDVR, которая без зонда неотличима от официальной.
- Зонд, по логу которого видно, какое значение режима означает «кино» и кто включает кинотеатр.

**Non-Goals:**
- Менять режим или как-либо влиять на картинку (это следующая заявка).
- Обновлять форк до 0.20.x.
- Автоматическая установка без участия пользователя (установка и откат запускаются вручную).

## Decisions

1. **Копия исходников в папке `edvr/` внутри репозитория проекта**, а не git-submodule и не отдельный репозиторий.
   Причина: мы развиваем код сами, апстрим только для подсказок; одна папка и один репозиторий проще для пользователя.
   В `edvr/UPSTREAM.md` записываем тег, хеш коммита, дату и лицензию. Альтернатива submodule отвергнута: сложнее в
   обращении и подразумевает слежение за апстримом.

2. **Python ставим через `winget` (Python 3.12) + `pip install -r tools\requirements.txt`.** Это стандартный путь из
   `docs/building.md` EDVR. Установка программ на машину требует согласия пользователя — это отдельная задача с подтверждением.

3. **DLSS сохраняем**: перед сборкой выполняем `tools\fetch_ngx.py`, как в документации EDVR. Без этого наша сборка
   отличалась бы от установленной (в меню F8 пропал бы DLSS).

4. **Зонд — отдельный модуль `src/d3d11/native_vr_probe.cpp/.h`** по образцу Explorer Cam: тот же `CodeHook`,
   та же проверка билда и пролога, тот же `Log`. Подмешиваем его в существующий порядок инициализации EDVR рядом
   с Explorer Cam. Своя копия механики хуков отвергнута: дублирование и риск ошибок в самой опасной части.

5. **Обработчики — «вызвать оригинал, ничего не менять».** Execute: прочитать запрошенный режим `*(*(this+0x10)+8)`
   и вычислить применённый так же, как игра (≥3 → 1), взять `_ReturnAddress()` → смещение в exe, затем вызвать оригинал
   с теми же аргументами. Activate/Deactivate: записать `this`, флаг `+0x20` до вызова, адрес возврата, затем оригинал.
   Чтение полей игры — под SEH (`__try`), как в Explorer Cam: при сбое чтения пишем «не прочитано», но оригинал вызываем всегда.

6. **Запись в лог не из потока игры, а через лок-фри кольцевую очередь**, которую раз в кадр разбирает кадровый поток
   EDVR (свой тик рядом с `tkExplorerCam` в `device_hook.cpp`) и пишет в `Log`. Так требует правило EDVR: хуки игры
   не пишут лог, не берут блокировок и ничего не выделяют (`explorer_cam.h`, раздел THREADS) — иначе возможна
   взаимная блокировка. Ограничитель частоты работает при разборе: одинаковое событие — не чаще раза в секунду,
   сводка «повторов пропущено: N»; переполнение очереди тоже считается и попадает в сводку.
   Адрес оригинала публикуется в колбэке `prepare` у `CodeHook::install` до того, как патч станет активным
   (иначе первый вызов игры может прийти раньше, чем адрес оригинала сохранён).

7. **Настройка** — ключ `native_vr_probe` в секции `[experimental]` `edvr.ini`, значения 0/1, по умолчанию 0
   в эталонном ini; в установленный у пользователя `edvr.ini` дописываем `= 1` отдельной задачей.
   Строки лога помечаем префиксом `native-vr-probe:`.

8. **Пометка сборки**: к строке версии в начале лога добавляем `EDVRonFOOT` (например, `v0.19.1-edvronfoot.1`).

9. **Установка/откат** — два `.bat` в `edvr/` проекта. `install_to_game.bat`: при первом запуске сохраняет
   официальные файлы EDVR (`d3d11.dll`, `nvngx_dlss.dll`, `Openvr\win64\openvr_api.dll`, `openxr_loader.dll`,
   `edvr_openxr.ini`) в `edvr_backup_edvronfoot\official-v0.19.1\` вместе со списком SHA-256, затем ставит нашу сборку
   **штатным** `tools\install_edvr.py --target steam --all` (он сам отказывается при запущенной игре, сверяет хеши
   и не трогает `edvr.ini` — правило из `edvr/AGENTS.md`: ставить только через него). `restore_official.bat`
   возвращает файлы из снимка и сверяет хеши со списком.

## Risks / Trade-offs

- [Полная сборка EDVR долгая и запускает много тестовых стендов] → первая сборка запускается в фоне; ускоренный
  режим `--dll-only` требует «зелёной» полной сборки, поэтому первая всегда полная.
- [Антивирус ругается на перехват кода — у EDVR уже есть ложное срабатывание Defender] → предупреждаем пользователя;
  при блокировке — исключение для папки игры.
- [Execute может вызываться не при выходе на ноги, а иначе, или режим ставится другим путём] → Activate/Deactivate
  кино-модуля всё равно покажут, кто включает кинотеатр; адрес возврата укажет следующую точку для Гидры.
- [Activate/Deactivate вызываются для всех видов, не только основного] → в логе пишем `this`, это позволит отличить экземпляры.
- [Сбой в обработчике уронит игру] → обработчики минимальные, чтение под SEH, при любом отказе установки хук не ставится.
- [Сборка без DLSS SDK меняет поведение] → `fetch_ngx.py` обязателен в инструкции; проверка — DLSS виден в меню F8.

## Migration Plan

1. Собрать, поставить нашу сборку с выключенным зондом, сравнить с официальной (корабль, F5 на ногах).
2. Включить зонд, пройти сценарий «корабль → ноги → корабль», собрать лог.
3. Откат: `restore_official.bat` возвращает официальные DLL из резервной копии.

## Open Questions

- Конкретное значение режима «кино» (0, 1 или 2) — ровно то, что должен показать лог; на план это не влияет.
