# Design

## Context

Зачем — см. `proposal.md`. Факты по новой сборке — `docs/research/native-vr-on-foot.md`, раздел
«Перенос на 334473».

Как сейчас устроен код (`edvr/src/d3d11/native_vr_probe.cpp`, `native_vr_probe_core.h`):
- `nativeVrProbeFrameBoundary()` при первом включении ключа зонда или `native_vr_on_foot` вызывает
  `nativeVrProbeInstall(..., checkIdentity = true)`. Тот сверяет PE stamp и SizeOfImage с 332841 (`kExpectedTimestamp`,
  `kExpectedImageSize`). При несовпадении он ничего не ставит, а `g_identityOk` остаётся false.
- Переключатель `nativeVrCinemaSwitchStep(address, ...)` получает
  `g_identityOk ? base + kCinemaSwitchRva (0x5E82B3E) : nullptr`. При nullptr он пишет строку «not build 332841».
- Удержание (`nativeVrProbeSetOnFoot(onFootKey && sourceArmed)`) требует хука источника `0x281AC10`. Без него в лог
  идёт строка «cannot work: the stereo mode source is not hooked ...; the game keeps its cinema». С байтом это уже
  неправда.
- Логика байта (`cinemaSwitchStep`: только 1 → 0, наш 0 → 1, «странное» значение — отказ) — чистая функция, её
  проверяет часть F стенда `native_vr_probe_test`.

Что найдено на 334473: узор `FF 90 B0 00 00 00 44 38 2D <disp32> 74 ?? 84 C0 75` по адресу `0x288A133`, ровно одно
совпадение в exe. Байт `0x5E85B8A` лежит в `.data` (флаги `0xC0000040`, чтение и запись), значение 1.

## Goals / Non-Goals

**Goals:**
- Переключатель находит байт сам, без таблицы сборок, со строгими проверками, и работает на 334473.
- Проверки сделаны чистыми функциями и покрыты стендом на синтетических буферах.

**Non-Goals:**
- Не переносить зонд и удержание на 334473: они остаются для 332841. Удержание в полётах `.6` ни разу не понадобилось.
- Не искать адреса Explorer Cam и других частей EDVR, привязанных к сборке.
- Не держать для 332841 отдельную ветку с жёстким адресом. Этой сборки у нас больше нет: лаунчер её заменил.

## Decisions

**1. Узор: вызов `vf_B0`, затем сравнение байта, затем ветвление.**
`FF [90-97] B0 00 00 00` — `call [reg+0xB0]`, «вид от первого лица на ногах?». За ним `[44|45] 38 [05|0D|..|3D]
<disp32>` — `cmp byte ptr [rip+disp], r8b..r15b`. Дальше `74 ?? 84 C0 75` — `je`, `test al, al`, `jne`. Адрес байта
считается так: адрес после инструкции `cmp` плюс `disp32`.
Регистры сделаны переменными: при перекомпиляции компилятор легко берёт другой. Структура вызова и сравнения
не меняется. Проверено на 334473: и строгий, и гибкий варианты дают одно совпадение.
*Альтернатива — идиома 3 → 5, 4 → 6 (`83 E8 03 74 ?? 83 F8 01 75 ?? 8D 58 05`).* Она тоже уникальна, но байт из неё
не вычислить. Остаётся запасной проверкой на будущее, в код не идёт.
*Альтернатива — таблица «сборка → адрес».* Ломается при каждом обновлении, отвергнута Димой (вариант 2).

**2. Строгие проверки, отказ — молча для игры и одной строкой в лог.**
- ровно одно совпадение (0 — «не найден», больше 1 — «найдено N»);
- адрес байта внутри образа и внутри раздела с флагом записи;
- значение байта 1 (0 — существующая ветка «уже 0, игры», иначе — существующая ветка «странное значение»).
Последняя проверка уже есть в `cinemaSwitchStep`, её не дублируем.

**3. Где искать: в памяти загруженного образа, по таблице разделов из заголовка PE.**
Разделы с флагом исполнения (`.text`) — для узора, раздел байта — для проверки записи. В коде нет абсолютных адресов
внутри узора, поэтому перемещения образа на него не влияют. Чтение памяти под SEH, как `sehCheckBytes`. Поиск один раз
при первой установке (`tried`), на кадровом потоке: проход по ~80 МБ с `memchr` по первому байту — десятки
миллисекунд. Это один подтормаживающий кадр при запуске, не на ногах.
*Альтернатива — отдельный поток.* Сложнее и даёт гонку с первым кадром; один кадр при запуске не стоит этого.

**4. Чистое ядро и тонкая обёртка.**
В `native_vr_probe_core.h` — `findCinemaSwitch(sections, readFn)` или эквивалент на буферах. Он возвращает число
совпадений, RVA байта и причину. Там же текст строки результата. В `.cpp` — только доступ к памяти образа под SEH.
Стенд даёт синтетические «образы»: одно совпадение, ноль, два, байт в разделе без записи, байт вне образа, разные
регистры.

**5. Строки лога.**
- Результат поиска одной строкой: `native-vr-on-foot: cinema-on-foot switch found at EliteDangerous64.exe+0x5E85B8A
  (the one call-then-compare in the game's code; PE stamp 0x..., image size 0x...)` либо `... not found: <причина>;
  the game keeps its cinema`.
- `formatSwitch` получает найденный RVA вместо `kCinemaSwitchRva`. «not build 332841's 1» заменяется на «not the
  game's 1».
- Строка про удержание: если источник не захвачен, а байт найден — «the hold (build 332841 only) is not installed;
  the head camera switch works without it». Иначе — как сейчас.
- `kCinemaSwitchRva` удаляется: его никто больше не читает. Это константа в коде, а не ключ настроек.

**6. Установка без слепка.**
`edvronfoot_game.ps1 -Action Install` без слепка требует официальный v0.19.1 в папке игры, а там сейчас пусто.
Поэтому `.8` ставится тем же вызовом, что делает скрипт, напрямую: `tools\install_edvr.py --target <папка игры>
--all --tag edvronfoot`, игра при этом закрыта. Живой `edvr.ini` восстанавливается копией из
`%TEMP%\claude\edvr_ini_before_recon.ini` до первого запуска: копия от 20.10, зеркало EDVR в `%LOCALAPPDATA%` старше,
от 19.10. Сам скрипт не правим: слепок понадобится только для отката, и его можно будет сделать позже из официального
архива EDVR.

## Risks / Trade-offs

- **[Риск] Узор совпадёт в чужом месте после будущего обновления.** → Требуется ровно одно совпадение. Байт должен
  лежать в записываемых данных и быть равен 1. Пишется только 1 → 0, и это видно в логе. Худший случай — кинотеатр
  на ногах не выключится, игре вред невозможен: 0 в этом байте — родное значение «без кинотеатра».
- **[Риск] Frontier изменят код так, что узор пропадёт.** → Строка «не найден» в логе, на ногах кинотеатр. Дальше —
  новая статика по разделу «Перенос на 334473» как образцу.
- **[Риск] Обновление сломало что-то в самом EDVR** (подмена разрешения, панели). → Полёт и лог покажут. Записывается
  отдельно, в эту заявку не входит.
- **[Компромисс] Удержание-страховка на 334473 недоступно.** → В `.6` и `.7` она ни разу не срабатывала, байт делает
  всю работу. При нужде её перенос — отдельная заявка.
- **[Риск] Подтормаживание при поиске.** → Один раз за сессию при запуске. Строка результата пишет время поиска в мс:
  если оно велико, это будет видно.

## Migration Plan

1. Сборка `.8`, все проверки, коммит, тег, `--dll-only`.
2. Установка при закрытой игре через `install_edvr.py`, восстановление `edvr.ini`, `Status` → `.8`.
3. Полёт Димы, проверка лога.
Откат: официального слепка нет. Если `.8` не годится, ставится `.7` из тега тем же `install_edvr.py`.
