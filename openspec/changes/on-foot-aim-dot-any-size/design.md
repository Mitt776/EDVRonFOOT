# Design

## Context

Как модуль работает сейчас (`edvr/src/d3d11/aim_dot_core.h`, `aim_dot.cpp`, сборка `.61`):

- Атлас находится по пропорции 1.161 при любом размере. Прямоугольник центра считается в долях атласа: при 2076x1787
  это 12x11, при 1868x1608 — 10x11, при 1245x1072 — 7x8, при 2768x2383 — 14x15.
- Каждый кадр строки центра (высота — прямоугольник центра) копируются во всю ширину атласа в кольцо из трёх копий.
  Копия читается без ожидания и решает следующий кадр.
- `readRow` ищет вдоль полосы окно `kPatternW`x`kPatternH` (12x11), ближе всех к узору `kPlainDot`. `readCentre`
  решает «обычная» по сумме яркости 3798 ±15%, пятну до 7x7 и краю окна.
- Всё это стоит за `patternFor(w, h)`, то есть только при 2076x1787. На другом размере `readAndCopy` пишет
  `formatNoPattern` и решает «не обычная», ничего не копируя.
- Вне ног (`!onFoot`) модуль отдаёт атлас и свои текстуры (`releaseAll`). Новый выход на ноги начинается с чистого
  состояния.

Почему меняем — proposal.md. Что должно получиться — дельта `specs/on-foot-aim-dot/spec.md`.

## Goals / Non-Goals

**Goals:**
- Одно решение «обычная / другое» для любого размера атласа, и при 2076x1787 оно даёт ровно то же, что `.60`.
- Пороги выбираются по настоящим картинкам 1868 и 1245, а не на глаз: отсюда шаг разведки без стирания.

**Non-Goals:**
- Пропорция атласа на других шлемах. Признак оружия (числа индексов не зависят от размера). Формат строк, кроме новых.

## Decisions

### 1. Образец — структура, а не константы

В `aim_dot_core.h` появляется образец: окно `W`x`H`, яркость каждого пикселя окна, ожидаемая сумма, предел пятна.
`readCentre` и `readRow` берут образец параметром вместо `kPatternW/H`, `kPlainDot`, `kPlainSum`, `kSpotMax`.

- **2076x1787:** образец собирается из `kPlainDot` как есть (12x11, сумма 3798, предел 7). Стенд проверяет, что все
  старые образцы дают те же решения.
- **Другой размер:** окно = прямоугольник центра этого атласа, `centreOf(w, h)`. Это же окно модуль стирает, поэтому
  стирание и поиск совпадают по размеру сами. Яркость пикселей — узор `.42`, пересчитанный под окно по площади:
  каждый пиксель нового окна — среднее перекрытых им пикселей узора с весами. Сумма = 3798 · (w/2076) · (h/1787). Предел
  пятна = ⌈7 · w/2076⌉.

**Почему по площади, а не «ближайший пиксель»:** точка игры — векторная фигура со сглаживанием. Среднее по площади
сохраняет её яркость в сумме, а «ближайший» на 0.6 теряет или удваивает края.

**Отвергнуто — растягивать снимок до 2076 и гнать старый код:** при увеличении с 0.6 картинка мылится, пятно расползается
за 7x7, а край окна начинает светиться. Пороги пришлось бы менять всё равно.

### 2. Шаг 1: решение «на пробу»

В сборке шага 1 страж `patternFor` из `readAndCopy` уходит: копия и чтение идут на любом размере. Стирание при этом
разрешено только при 2076x1787. На другом размере решение считается, пишется в строки и сводку, а
`aimDotHideBeforeEyeComposite` выходит до стирания. Строки решения получают пометку `trial` (например,
`aim dot: centre plain (trial, not erased; …)`), чтобы по логу было видно, что точка видна по замыслу. Строки пикселей
(`centre pixels`) пишутся на «другое», как сейчас. Чтобы получить картинку обычной точки, на шаге 1 строка пикселей
пишется и для «обычной», но только на пробном размере.

Окно в строке пикселей — размера образца (`W`x`H`), а не всегда 12x11. Предел длины строки (`kPixelsLineCap` 1100)
держит до 12x11. Окна больше (2768: 14x15) режутся по пределу с пометкой `…`. Для разведки хватает 1868 и 1245, они
меньше.

**Почему не стирать сразу по пересчёту:** ошибка в пересчёте сотрёт точку пистолета или инструмента. При 1245 точка
4x3 пикселя, и запас 15% против +41% у инструмента — догадка. Один полёт без риска дешевле, чем разбор, почему пропал
прицел.

### 3. Шаг 2: стирание и самообучение

- Стирание разрешается на любом размере, пометка `trial` уходит, пороги уточняются по картинкам шага 1.
- **Самообучение** (только не 2076x1787). Счётчик подряд идущих чтений, где: признака оружия нет, решение по
  пересчитанному образцу — «обычная», `at` в пределах ±1 от левого края прямоугольника центра. На пятом таком чтении
  окно копируется в образец: яркость по пикселям, сумма = сумма окна, окно и предел пятна — от пересчитанного.
  Счётчик сбрасывается любым другим чтением.
- После находки поиск (`readRow`) и узнавание (`readCentre`) идут по выученному образцу. Пересчитанный остаётся
  стражем: выученное принимается, только если его сумма в пределах 15% от пересчитанной (иначе строка `learn refused`, и
  поиск продолжает идти по пересчитанному).
- Выученное живёт в состоянии модуля и уходит вместе с `releaseAll` (вне ног) и при смене размера (`noteSize`).

**Почему пять чтений у центра:** сразу после выхода на ноги точка лежит в центре (`.59`: сдвиг сбрасывается). Пять
чтений — меньше 0.2 с, а случайное совпадение (метка, подсказка в центре) за пять кадров подряд маловероятно. Точку,
уехавшую по строке, не учим: на ней видна дробная размытость (`.59`, отличие от узора 70–100), а образец должен быть
резким.

**Почему на 2076 не учимся:** узор `.42` облётан в `.60` по всем пунктам. Выученный образец ничего не добавит, а
риска прибавит.

**Отвергнуто — учиться без стража:** если первый кадр на ногах окажется не тем, модуль выучит ерунду и будет стирать
её до следующего выхода.

### 4. Строки

- `aim dot: pattern for WxH: scale S (window WxH, sum N, spot ≤ K)` — на каждый новый размер, вместо
  `formatNoPattern` (удаляется вместе со стражем).
- `aim dot: learned the plain dot for WxH (sum N, scaled N0, at=x…)` / `aim dot: learn refused for WxH (sum N, scaled
  N0)` — шаг 2.
- Подпись `centre plain/other` и сводка без изменений, кроме пометки `trial` на шаге 1.

## Risks / Trade-offs

- [На 1245 точка 4x3, и сумма по площади отходит от настоящей больше 15%] → шаг 1 это и покажет. Порог для мелких
  атласов — по картинке, новой задачей.
- [Точка инструмента на мелком атласе по сумме ближе к обычной, чем на 2076] → в шаге 1 Дима достаёт инструменты на 1245.
  Строки пикселей покажут их суммы. Если запас меньше 10%, к сумме добавляется проверка пика или числа ярких.
- [Высота полосы на мелком атласе (8 строк) меньше, чем нужно, если точка уезжает по вертикали] → `.59` видел только
  сдвиг по строке. Если на 1245 найдём другое, это новая задача.
- [Выученный образец снят с кадра, где точку уже сдвинуло] → признак `at` у края центра ±1. Страж по сумме.
- [Окно 14x15 на 2768 не влезает в строку пикселей] → обрезка с пометкой; на 2768 не летаем, нужно только стенду.

## Migration Plan

- Работа в ветке `change/on-foot-aim-dot-any-size` и в PR в `main`. Сборки `.62` (шаг 1) и `.63` (шаг 2) ставятся на
  игру через `install_edvr.py`. Живой `edvr.ini` не трогается.
- Откат: ключ `show` выключает модуль сразу (без перезапуска). Полный откат — установка релиза 0.1.0.
- Номера `.62`/`.63` — только в документах. Теги разработки после релиза не ставятся, сборку в логе проверяем по
  `--expect-build <коммит>`. Выпуск 0.1.1 — после слияния и только по «да» Димы.
