# Design

## Context

Мотив — в proposal.md (Why). Что известно: исследование, разделы «Прогулка `.21`» и «После `.21`: скрины Димы».

Узел HUD рисует листы 36–39 через `0x58F0F0`; зонд `.21` уже держит «окно узла» (поток, вид, место) и лист окна
(перехват `0x592090`). Каждое рисование D3D11 доходит до `beginPanelOverride` (`vscreen.cpp`), где зонд зовётся до
ветки чужого контекста (`onFootHudProbeNoteDraw`). В кинотеатре на планете все рисования узла шли на своём контексте:

```
лист 38: VS C4B4B334, 3600/96 индексов, t2 = панель 3564x2140 / 1521x1402 (подсветка)
         VS B10B032B, 6 индексов (квадрат), t0 = панель 4089x3521
лист 39: VS B10B032B, 3600 и 624 индекса, t0 = панель 3564x2140;  96 индексов, t0 = 1521x1402
цель рисования кинотеатра 3408x1917 (1920x1080 x 1.775); в стерео глаз 2720x2976
```

Готовый приём в EDVR: `AnimatedVertexHistory` (`animated_vertex_history.h`) повторяет рисование с потоковым выводом.
Это геометрический шейдер из кода вершинного (`CreateGeometryShaderWithStreamOutput`, `D3D11_SO_NO_RASTERIZED_STREAM`),
топология point list, `SOSetTargets`, то же рисование настоящей функцией, потом восстановление. Код шейдера он держит в
private data шейдера (`rememberShader`), но только для своих семейств. Создание шейдеров идёт через `hookedCreateVS`
(`device_hook.cpp`), где хэш уже посчитан. В `vscreen.cpp` настоящие функции рисования — `realDraw*` в состоянии
контекста. Разбор контейнера DXBC и сигнатур — `dxbc_container.h`. Запись в папку логов — образцы в
`flat_pixel_capture.h` (`Config::get().logDir()`, `ensureDirectory`), BMP — `temporal_pass.cpp`.

## Goals / Non-Goals

**Goals:**
- одна прогулка в кинотеатре даёт для каждой сетки узла HUD её место на экране и отображение панели, в ситуациях:
  HUD на планете, диалог, меню лифта, меню двери, колесо;
- по картинкам панелей видно, в какой панели что лежит (HUD, диалог, меню);
- «не снято» отличимо от «не рисовалось»: у каждого отказа причина, у сводки строка «no snapshot».

**Non-Goals:**
- абсолютные углы: позиция после вершинного шейдера уже в пространстве экрана, поэтому снимок даёт доли экрана; общий
  угловой размер листа подбирается ключом в шлеме;
- снимок рисований чужого контекста (там нет тени и настоящей функции рисования этого пути);
- разбор материалов и записи — это делает зонд `.21`, он остаётся как есть.

## Decisions

### 1. Повтор рисования с потоковым выводом, а не чтение буферов и матриц

Вариант «прочесть вершинный буфер и матрицы из буфера констант» требует знать раскладку вершин и место матрицы для
каждого шейдера (`B10B032B`, `C4B4B334` и тех, что рисуют диалоги и меню на станции, — их ещё не видели). Повтор с
потоковым выводом берёт ровно то, что выдал шейдер игры: позицию отсечения и координату текстуры. Приём уже работает в
EDVR (`AnimatedVertexHistory`).

Как:
- в `onFootHudProbeNoteDraw` (окно узла открыто, свой контекст, форма требует снимка по решению 3) зонд сохраняет GS
  (с классами), цели SO и топологию;
- ставит свой GS с потоковым выводом и point list, цель SO — свой буфер, зовёт то же рисование настоящей функцией
  (`realDraw*`, передаётся из `vscreen.cpp` указателем) с теми же аргументами;
- возвращает GS, SO и топологию; копирует буфер SO в промежуточный (staging) из кольца на 4.

Point list при рисовании с индексами выдаёт по вершине на индекс: размер вывода = число индексов x экземпляры, без
сборки треугольников. Отказ (причина в сводке): GS или HS/DS уже стоят; нет кода шейдера; вывод больше 65536 вершин;
кольцо занято; рисование не на своём контексте.

### 2. Что выводить: позиция и первая координата текстуры из сигнатуры

Сигнатура вывода шейдера (`OSGN`/`OSG5`) разбирается из кода (`dxbc_container.h`). Объявление SO:
`SV_POSITION` (4 компоненты) и первый `TEXCOORD` с двумя и более компонентами (берём 2). Если `TEXCOORD` нет — только
позиция, строка с пометкой «no texture coordinate». GS с SO создаётся один раз на шейдер и хранится по адресу шейдера.

### 3. Частота: форма, место, 5 секунд, строка только при изменении

Ключ формы — тот же, что в `.21` (лист, вид, место, свой контекст, вид и число рисования, хэши VS/PS, t0). Первый снимок
формы в месте — сразу, дальше не чаще раза в 5 с. Итог снимка (решение 5) сравнивается с прошлым этой формы: строка и
файлы — при первой встрече и если рамка или сетка 3x3 сдвинулась больше чем на 0.01 экрана. Таблица форм для снимков —
256 мест, как формы `.21`; переполнение — счёт.

### 4. Чтение результата без ожидания GPU

Промежуточный буфер читается на том же контексте при следующих рисованиях окна (`Map` с `D3D11_MAP_FLAG_DO_NOT_WAIT`;
`DXGI_ERROR_WAS_STILL_DRAWING` — попробовать позже, через 30 кадров без ответа — отказ «readback timeout»). Прочитанные
вершины копируются в память зонда и передаются кадровому потоку (одна очередь, без блокировок на пути рисования).
Картинка панели (t0, или t2 у `C4B4B334`) копируется так же — только когда снимок даст строку и формат 8 бит RGBA
(форматы 27/28/29/87/88/90/91); у размера панели верхняя граница 4096x4096.

### 5. Итог снимка на кадровом потоке

- место на экране вершины: `x/w`, `y/w` → доли экрана 0..1 (верх — 0), глубина `w`; вершины с `w <= 0` отбрасываются
  и считаются;
- рамка сетки на экране и рамка видимой части панели (min/max u, v);
- сетка 3x3: для точек панели (u, v) из {0, 0.5, 1} внутри рамки видимой части — место на экране ближайшей вершины по
  (u, v);
- изгиб: углы сетки 3x3 задают плоский четырёхугольник; наибольшее отклонение остальных 5 точек от билинейной
  интерполяции углов — в долях экрана;
- пропорция панели = ширина/высота, чтобы потом сопоставить панель кинотеатра (3564x2140) с панелью стерео
  (2412x1449) той же пропорции.

### 6. Файлы на кадровом потоке

Папка `<logDir>\hud_layout\<время запуска>\`. Имена: `s<номер снимка>_list<лист>_<vs8>_<WxH>.csv` и `.bmp`. CSV:
`i,x,y,w,u,v`. BMP — 32 бита, как в `temporal_pass.cpp`, каналы как есть (sRGB-формат не пересчитывается). По 48
каждого вида за запуск.

### 7. Код вершинных шейдеров

В `hookedCreateVS`, если ключ зонда включён при запуске (читается один раз при старте), код шейдера кладётся в private
data шейдера тем же ключом, что у `AnimatedVertexHistory::rememberShader` (общий ключ — общий код, без второй копии).
Счёт байт; сверх 64 МБ — строка в лог и больше не запоминается. Шейдеры с `linkage` не запоминаются.

## Risks / Trade-offs

- [Повтор рисования меняет состояние контекста] → сохраняются и восстанавливаются GS (с классами), SO и топология;
  стенд проверяет «до = после» на подставном контексте; растеризация выключена (`NO_RASTERIZED_STREAM`), цели рисования
  не трогаются.
- [Память кода шейдеров] → только при включённом ключе на запуске, предел 64 МБ, строка в лог.
- [Копия большой панели (3564x2140 ≈ 30 МБ) тормозит] → только когда снимок даёт строку, не больше 48 за запуск,
  чтение без ожидания.
- [Диалоги и меню на станции рисуются шейдерами, которых нет в списке] → снимаются все рисования окна узла, не по
  списку хэшей.
- [Рисования узла на станции идут на чужом контексте] → отказ «foreign context» в сводке; тогда снимок там невозможен, и
  это ответ сам по себе (следующий шаг — тень чужого контекста).
- [Сетка 3x3 по ближайшей вершине груба у редких сеток (квадрат 6 индексов)] → полная раскладка есть в CSV.

## Migration Plan

Ключ тот же, по умолчанию 0. После разбора прогулки — `on_foot_hud_probe = 0` в живом `edvr.ini`. Откат — прежняя
сборка `.21` через `install_edvr.py`.
