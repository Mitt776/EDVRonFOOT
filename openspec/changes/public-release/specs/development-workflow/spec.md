## Purpose

Как идёт разработка EDVRonFOOT через GitHub: каждая заявка OpenSpec — своя ветка и pull request, облёт до слияния,
понятная история в `main`.

## ADDED Requirements

### Requirement: Заявка — ветка — pull request
Работа по каждой заявке OpenSpec SHALL идти в своей ветке `change/<имя-заявки>` от `main` и попадать в `main` только
через pull request. В `main` SHALL NOT коммитить напрямую, кроме мелких правок документов. Pull request SHALL ссылаться
на заявку и нести план ручной проверки (облёта).

#### Scenario: Новая заявка
- **WHEN** начинается заявка `foo`
- **THEN** создаётся ветка `change/foo`, коммиты идут в неё, на GitHub открыт PR в `main` со ссылкой на
  `openspec/changes/foo/`

#### Scenario: Слияние
- **WHEN** облёт прошёл и Дима сказал «да»
- **THEN** заявка архивирована в той же ветке, PR слит в `main`, ветка удалена, `main` отправлен на GitHub

### Requirement: Шаблон pull request
Репозиторий SHALL содержать шаблон PR с разделами: заявка, что изменилось простыми словами, как проверить руками (облёт),
результат облёта, ключи `edvr.ini` (новые, временные, удалённые).

#### Scenario: Открытие PR
- **WHEN** открывается PR на GitHub
- **THEN** его описание заполнено разделами шаблона

### Requirement: Почта в коммитах
Все новые коммиты SHALL подписываться адресом GitHub noreply аккаунта `Mitt776`, не личной почтой.

#### Scenario: Новый коммит
- **WHEN** делается коммит в этом репозитории
- **THEN** у автора адрес `…+Mitt776@users.noreply.github.com`

### Requirement: Выпуск
Выпуск SHALL делаться из `main` после слияния: тег `edvronfoot-vX.Y.Z`, полная сборка со всеми проверками, архив
релиза, релиз на GitHub с архивом и списком изменений. Выпуск SHALL NOT публиковаться без «да» Димы.

#### Scenario: Новый выпуск
- **WHEN** Дима говорит «выпускаем 0.2.0»
- **THEN** на `main` ставится тег, собирается и проверяется архив, на GitHub появляется релиз `EDVRonFOOT 0.2.0` с ним
