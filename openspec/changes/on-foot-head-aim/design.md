# Design

## Context

Зачем — proposal.md. Опора — зонд `.35/.36` (доклад, «Зонд прицела головой», «Полёт `.35`/`.36`»):

- **Рычаги** — два геттера в таблице HMC (334925), подменённые ячейки `+0x5206B58` (угол 1) и `+0x5206B70` (угол 2):
  - угол 1, `vf+0xB0` = `[0x6F0] − [0x710]` — наклон, радианы, `+` = вниз, стиком от −85° до +75°;
  - угол 2, `vf+0xC8` = `[0x70C] + [0x6FC]` — поворот взгляда относительно тела, `+` = вправо. Обычно ~0, при
    повороте стиком на миг до −40° (тело догоняет взгляд).
  - Оба двигают ствол, точку прицела и камеру. Ходьба идёт по телу.
- **Игрок** — только HMC камеры (цепочка `+0x10743CB` → «глаз» → `[eye+0xD0]`), подтверждённый геттерами в ту же
  секунду. Геттеры видят 8–16 HMC даже в одиночестве.
- **Камера** = поза шлема для игры × матрица «глаза». «Глаз» = тело × поворот(угол 2) × наклон(угол 1): сначала
  угол 2, потом угол 1.
- **Компенсация поворота** — `turnAboutVertical(pose, +сдвиг)` (`plus`) — держит мир. Компенсации наклона нет.
- **Такт**: защёлка раз в кадр рантайма (около 36 в секунду по сводке), угол игрока читается 1–5 раз на защёлку,
  `zero_frames=0`. Под качанием мир стоял.
- **Вход канала** уже несёт настоящую позу головы кадра в сидячем пространстве (`EdvrNativeFrameInput::physicalHead`
  = `headToLocal`), до сдвигов `.33/.34`. Защёлка зонда зовётся в том же `beginFrame` (`native_frame.cpp:307`), где
  эта поза есть.
- **Меню на ногах** знает `on_foot_hud`: слои `Lift`, `Answers`, `Dialog`, `Mission`, `Trader`, `Biologist`, `Arms`
  со своими «держаниями». Наружу этот признак пока не выходит. Журнал даёт `journalGuiFocus`.

## Goals / Non-Goals

**Goals:**
- Ствол за шлемом по обеим осям, мир стоит точно (компенсация того же числа, что ушло в геттер в этом кадре).
- Одна переменная на пробу в полёте — знак компенсации наклона, переключается в F8.
- Без ключа — побайтно поведение `.36`.

**Non-Goals:**
- Худ (`on-foot-hud-lazy-yaw`), очистка ключей и зонда (`on-foot-aiming-cleanup`).
- Поворот самого тела за головой. Зонд показал, что угол 2 — взгляд относительно тела, а тело живёт в его матрице.
  Для прицела этого хватает, ходьба по телу Диму устраивает (проверить в полёте).
- Крен головы в прицел: остаётся в позе для игры, как сейчас.
- Свои параметры фильтра для LT. Если понадобятся — по итогам полёта.

## Decisions

### 1. Хуки зонда — общие, фича — новый расчёт в той же защёлке
Подменённые ячейки, опознание игрока и защёлка уже облетаны. Фича их не дублирует: `head_aim_probe.cpp` становится
общим входом. Защёлка решает, кто ведёт кадр:
- ключ фичи не `off` → фича (сдвиги зонда молчат, `watch` пишется);
- иначе → зонд как в `.36`.

Чистая часть фичи — новый `head_aim_core.h` (фильтр, углы из позы, предел, набег, строки), стенд — отдельный
`tools\head_aim_test` в гейте `build.bat`. Зонд со своим стендом не меняется по сути. Уберёт его очистка.
- Альтернатива: вынести хуки в новый модуль сейчас. Отказ: двигать облетанный код ради модуля, который проживёт
  одну-две ступени, — лишний риск. Переезд — в очистке.

### 2. Что отдают геттеры
Защёлка кадра считает два числа: `yaw` и `pitch` (радианы). Геттеры игрока отдают:
- угол 2: `оригинал + yaw` — стик и отставание тела живут как раньше;
- угол 1: `оригинал + (pitch − оригинал)·доля`, то есть при доле 1 ровно `pitch`. Стик наклона при этом перестаёт
  влиять, при набеге/уходе переход плавный.

`pitch` в знаке игры: `+` = вниз, то есть минус наклон шлема вверх.
- Альтернатива для наклона: «оригинал + наклон шлема». Отказ: решение эксплора — наклон только от шлема, стик
  мешал бы (одно движение — две причины).
- NPC: условие «HMC = игрок» как в зонде; защёлка старше 250 мс не действует.

### 3. Углы из позы шлема
Из `physicalHead` кадра: вектор взгляда `f = −(третий столбец поворота)`. `yawHead = atan2(f.x, −f.z)` (вправо `+`),
`pitchUp = atan2(f.y, √(f.x²+f.z²))`. Крен не берётся. Поза — настоящая, сидячая, recenter ставит ноль «вперёд»;
сдвиги `.33/.34` на неё не влияют (они только переносят).
- Нет позы в кадре (`valid = 0`) → берутся углы прошлого кадра, фильтр стоит. Больше 250 мс без позы → уход в ноль.

### 4. Фильтр — one-euro
Отдельно на поворот и наклон, по времени защёлки (`dt` из часов, как в зонде, не больше 0,1 с). Начальные параметры:
`min_cutoff = 1.0 Гц`, `beta = 0.5`, `d_cutoff = 1.0 Гц` (единицы — радианы и секунды). Это обычные стартовые
значения для поворота головы: на покое срез ~1 Гц гасит дрожь в доли градуса, при быстром повороте срез растёт и
отставание падает до кадра-двух. Значения — константы в `head_aim_core.h`, ключами не выносятся. Подбор — по полёту
(сравнение `on` и `raw`).
- Поворот фильтруется с развёрткой через ±180° (разность углов берётся по кратчайшей), иначе голова «за спиной»
  дала бы скачок. На деле упирается в предел ±90° раньше.
- `raw` — фильтр пропускается.
- Альтернатива: мёртвая зона. Отказ (эксплор): постоянная ошибка до ширины зоны.

### 5. Предел и набег
- `yaw = clamp(доля · yawFiltered, ±90°)`. Предел считается после фильтра: компенсация берёт то, что отдано
  геттеру, поэтому за пределом мир всё равно стоит (просто голова «обгоняет» ствол).
- Доля 0..1, набег и уход за 0,5 с, как в зонде. Цель 1 только если: ключ не `off`, на ногах по журналу,
  `native_vr_on_foot`, игрок опознан, рантайм спросил канал 8, нет открытого меню и `GuiFocus` равен 0 (или журнал
  его не знает). Причина ухода запоминается для строки лога.
- Меню: `on_foot_hud` выставляет атомарный признак «держится слой, кроме `Hud`» (новая функция-читатель рядом с
  `onFootHudWantsDraws`).
- `pitch` при доле < 1 — смесь (решение 2), так что уход в меню возвращает и стик наклона.

### 6. Компенсация позы: поворот, затем наклон
Камера = тело × R_y(угол 2) × R_x(угол 1) × поза. Чтобы картинка совпала с «тело × поза», поза для игры должна быть
`R_x(угол 1)⁻¹ · R_y(угол 2)⁻¹ · поза`, где углы — ровно прибавка этого кадра:
1. поворот вокруг вертикали сидячего пространства на `+yawAdded` (`turnAboutVertical`, знак `plus` из зонда);
2. затем поворот вокруг горизонтали сидячего пространства (ось X) на `pitchAdded·знак`, где `pitchAdded = угол
   1 на выходе − оригинал` (в знаке игры).

Ожидание по математике: при голове вверх на φ поза шлема = R_x(+φ), угол 1 = −φ, и правый поворот на `+угол 1` даёт
`R_x(−φ)·R_x(+φ) = I` — то есть знак `plus`, если у `turnAboutVertical` и нового `turnAboutHorizontal` одно соглашение
(правый винт). Но порядок «сначала угол 2» и соглашение игры — из статики, а не из полёта. Поэтому знак наклона —
временный ключ, первая проверка полёта.

`pitchAdded` зависит от оригинала угла 1, а его видит только геттер. Поэтому `d3d11` берёт оригинал игрока из
последнего вызова геттера (сохраняется в атомик) и шлёт рантайму `pitchAdded` прошлого вызова. Оригинал при
неподвижном стике меняется медленно, и ошибка меньше кадра стика. Это тот же порядок, что у зонда для поворота
(защёлка до сборки «глаза»).
- Альтернатива: слать рантайму сам `pitch` и вычитать «наклон шлема». Отказ: не учтёт оригинал игры при доле < 1.

Порядок в рантайме: ноль `.34` → ведущий глаз `.33` → поворот → наклон. Там же, где сейчас поворот зонда:
`render.pose`, `game.pose` и ответ `locateHeadOwned`. Позы слоя — настоящие.

### 7. Канал версии 8
В конец `EdvrNativeFrameOutput` — два поля: `headAimPitchRad` (наклон позы, со знаком, уже с ключом знака) и
`headAimFeature` (1, пока фича ведёт кадр, для строки рантайма). `headAimYawRad` остаётся общим полем поворота.
- Фича (и только она) требует 8: защёлка от рантайма 7 вернёт поворот зонда как в `.36`, а фича не включится
  (причина `channel`). Старый прокси с новым рантаймом: рантайм спускается на 7/6 и читает 0.

### 8. Ключи
- `experimental.native_vr_on_foot_head_aim` = `off`/`on`/`raw`, `# ui:` в `edvr.ini`, по умолчанию `off`.
- `experimental.native_vr_on_foot_head_aim_pitch_comp` = `plus`/`minus`/`off`, по умолчанию `plus`.
Оба временные: в `## Status` доклада, уходят в `on-foot-aiming-cleanup`, где Диме будет задан вопрос, оставить ли
вкл/выкл настройкой.

### 9. Строки лога
- `head aim: key=on pitch_comp=plus`; `head aim: … not understood, reads …`;
- `head aim: on` / `head aim: off (ship|menu|focus|player|key|channel)` — на краях доли;
- `head_aim_feature,frames=…,active=…,max_yaw_deg=…,max_pitch_deg=…,capped=…,max_lag_deg=…,channel=…` раз в 30 с на
  ногах при ключе не `off`, с нулями тоже; `max_lag_deg` — наибольшая разница «шлем − после фильтра»;
- рантайм: `head_aim_runtime,…` получает `pitched=…,max_pitch_deg=…` в конце строки. Пишется, пока зонд или фича
  действуют, или при канале ниже 8.

### 10. Такт поправки (`.38`, после полёта `.37`)
Полёт `.37`: при повороте головы мир дёргается, у зонда `.36` этого не было. Мир стоит, только если угол, с которым
игра собрала камеру кадра, равен углу, на который рантайм повернул позу того же кадра. Защёлка меняет угол в
`beginFrame`, а игрок читает угол 1–5 раз за кадр в разные моменты (`per_frame=1..5`). Если камера иногда собирается
до защёлки (со старым углом), а поза уже повёрнута на новый, мир прыгает на поворот головы за кадр: при 36 кадрах в
секунду и 100°/с это ~3°. У зонда сдвиг за кадр почти не менялся, поэтому рассинхрон не был виден.
- **Момент камеры** — вызов матрицы «глаза» с адреса камеры (`eyeMatrixDetour`, тот же адрес возврата, что опознаёт
  игрока). В этот момент снимается снимок углов фичи, которые сейчас в силе (`yaw`, `pitchAdded`, уже с ключом
  знака), и номер защёлки.
- **Счётчик:** граница кадра игры — `headAimProbeFrameBoundary`. На каждый кадр игры — была ли защёлка и сборки
  камеры до неё и после неё. Раз в 30 с на ногах при ключе не `off`:
  `head_aim_sync,frames=…,cam_before=…,cam_after=…,cam_none=…,cam_multi=…,mode=latch|camera` (`cam_before` — кадры,
  где камера собиралась только до защёлки, `cam_after` — только после, `cam_none` — ни разу, `cam_multi` — больше
  одного раза). Классификация — чистая функция в `head_aim_core.h` со случаями на стенде.
- **Ключ** `experimental.native_vr_on_foot_head_aim_sync` = `latch` / `camera`. `latch` — как в `.37`. `camera` —
  защёлка по-прежнему обновляет углы для геттеров, а рантайму отвечает снимком последнего момента камеры (если с
  прошлой защёлки камера не собиралась — значениями новой защёлки). Это верно, когда камера кадра собирается до его
  защёлки; `latch` — когда после. Какой порядок у игры — покажет счётчик, какой режим стоит — Дима.
- Если счётчик покажет смешанный порядок и ни один режим не уберёт дёрганье — следующий шаг решаем по данным (не
  гадать): например, менять угол для геттеров только на границе кадра игры.
- Альтернатива: сразу «правильный» вариант по статике. Отказ: порядок вызовов игры статикой не виден, а живой ключ
  с счётчиком отвечает за один полёт.

### 11. Стик наклона в поправке (`.38`)
Полёт `.37`: стик наклона не двигает ни ствол, ни мир на ходу, но сдвигает взгляд относительно ствола (при
доставании оружия ствол на ~10° выше взгляда; по логу стик держался около +8°). Две модели камеры:
- А: камера = тело × R_y(угол 2) × R_x(угол 1) × поза, стик входит в угол 1. Тогда поправка на `pitchAdded =
  угол 1 на выходе − оригинал` оставляет в картинке наклон стика `o`: взгляд смещён от ствола на `o`. Верная поправка
  — на `pitchTarget·доля` (стик снимается и с картинки).
- Б: игра сама вычитает стик из камеры. Тогда верна поправка `.37`.
Статикой не различить → ключ `experimental.native_vr_on_foot_head_aim_stick_comp` = `off` (`.37`, `pitchAdded`) /
`on` (`pitchTarget·доля`). При доле 0 обе поправки 0, набег и уход плавные. В сводку `head_aim_feature` — поле
`stick_deg` (последний оригинал угла 1 игрока, в знаке игры).

## Risks / Trade-offs

- [Порядок углов в матрице «глаза» другой (наклон, потом поворот).] → Мир при взгляде вбок и вверх слегка
  крутится по крену. Проверка в полёте: 45° вправо и 30° вверх. Тогда — смена порядка в рантайме, правка без зонда.
- [Знак наклона неверный.] → Мир по наклону уходит вдвое, видно сразу; `minus` в F8.
- [Анимация рук на больших углах поворота (до 90°) выглядит странно, другие игроки видят выкрученный торс.] → Это
  внешний вид, не точность. Предел — константа, его можно уменьшить по полёту.
- [Рассинхрон угла камеры и поворота позы — мир дёргается при быстром повороте головы (подтверждено полётом `.37`).]
  → Решение 10: счётчик такта и ключ `sync`.
- [Стик наклона остаётся в картинке (модель А, решение 11).] → Ключ `stick_comp`; совет снять бинд убирает его
  совсем.
- [Сидячие анимации, лифт в движении, кресла в барах не ловятся признаками.] → Ствол там не важен, мир всё равно
  стоит (компенсация точная). Если мешает — в F8 `off`, и отдельный признак в очистке или в худе.
- [Фильтр по времени защёлки при неровных кадрах.] → `dt` ограничен 0,1 с; one-euro рассчитан на переменный шаг.
- [Признак «меню» мигает между кадрами, когда игра не перерисовывает панель.] → Используется «держание» слоя
  (`kHoldFrames`), как для показа.

## Migration Plan

Сборка `.37`, обе DLL через `install_edvr.py`. Ключ по умолчанию `off` — поведение `.36`. Для полёта Дима ставит
`on` в F8. Откат — `off` или установка `.36`. Ключи и зонд уходят в `on-foot-aiming-cleanup`.

`.38`: два новых временных ключа с умолчаниями `latch` и `off` — поведение `.37`. Канал не меняется (обе правки
внутри `d3d11.dll`), лестница версий как в `.37`. Верные режимы по полёту становятся умолчаниями отдельной правкой
до архива.

## Open Questions

- Параметры фильтра (`min_cutoff`, `beta`) — по ощущениям полёта; меняются константами, без новой спеки.
- Видят ли другие игроки поворот взгляда — смотреть, когда будет случай; на фичу не влияет.
