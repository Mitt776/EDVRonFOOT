# Design

## Context

Зачем — см. `proposal.md`. Адреса и разбор — `docs/research/native-vr-on-foot.md`, раздел «Разведка: где игра
рисует пеший HUD». Всё ниже относится к билду 334473: PE TimeDateStamp `0x6ACD513D`, SizeOfImage `0x640C000`. Ту же
метку проверяет `common/elite_oculus_profile.h`.

Что дочитано в Ghidra для этой заявки (вывод в scratchpad `re\d12.c`…`re\d16.c`):

- **Узел диапазона листов.** Конструктор `0x27F9D00`, vtable `0x52ED2C0`. Проход PostGUI (`0x28A71D0`) делает два
  таких узла на вид:
  - поле `+0xD8` — первый лист (`0x5E86020`), `+0xE0` — число листов;
  - первый узел — листы 36–39, второй — 40–46.
- **Рисование узла: `0x58F0F0 (node)`.** Через неё идут все узлы этого вида, не только PostGUI:
  - `S = *(node+0x108)`, контекст `ctx = *(S+0x60)`;
  - листы — массив `*(S+0x70)` длиной `*(S+0x44)`;
  - для каждого листа `i` из `[*(node+0xD8), +*(node+0xE0))` она зовёт `0x592090(ctx, list)` и `0x594EF0(ctx, list)`;
  - начало функции: `push rbx; push rdi; push r14; sub rsp,80h; mov rax,[rcx+108h]` — 16 байт без
    относительных операндов, `CodeHook` их переносит как есть.
- **Рисование листа: `0x594EF0(ctx, list)`.** Здесь два возможных места, где HUD пропадает:
  - **Маска.** Лист рисуется, только если `*(list+0x30) & *(ctx+0x270)` не ноль.
  - **Карман камеры.** Модели листа лежат цепочкой в кармане камеры: голова цепочки
    `*(list+0x40 + k*8)`, где `k = *(cam+0x8E8)`, `cam = *(ctx+0x250)`. Всего 64 кармана, `+0x40..+0x238`. Пустая
    голова — нечего рисовать.
- **Вид узла.** Базовый конструктор `0x57D1B0` кладёт объект вида в `node+0x110`; объект строит `0x6BE020`. У него:
  - `+0x10` — камера `PostGUIView` (поле прохода `+0x50`);
  - `+0x20` — строка имени `PostGUIView_%s` (строка игры: длина `+8`, символы с `+0x14`);
  - `+0x28` — бит вида, `+0x30` — номер бита.
- **Настройка камеры** (`0x28A7370`) копирует положение и проекцию главной камеры в камеру PostGUI только для вида 0.
  У камеры `+0x18` и `+0x250` — флажки, `+0x8D0` и `+0x8E0` — маски.

## Goals / Non-Goals

**Goals:**
- Одна прогулка отвечает, где теряется HUD в стерео: маска, пустой карман, модели в чужом кармане или всё на месте
  и дело дальше (тогда смотреть растеризацию).
- Сравнение видов 0 и 1 в одном логе.

**Non-Goals:**
- Не считать модели в цепочке поштучно: обход цепочки идёт через функции игры, зонд их не вызывает. Достаточно
  «есть / нет» для каждого кармана.
- Не перехватывать `0x594EF0`: её зовут на каждый лист каждого узла, а `0x58F0F0` — один раз на узел.
- Не трогать старый зонд `native_vr_probe` (он для 332841).

## Decisions

1. **Перехват после оригинала.** Хук вызывает `0x58F0F0` как есть и только потом читает поля.
   - Почему после: часть моделей кладётся в карман внутри `0x594EF0` (её первый цикл зовёт подавальщиков).
   - До вызова карман может быть ещё пуст, после вызова — заполнен, если модели вообще есть.
   - Отвергнуто: читать до вызова. Это дало бы ложное «пусто».
2. **Фильтр узлов — дёшево и сразу.** Хук сначала сравнивает vtable узла с `base+0x52ED2C0` и первый лист с 36 или
   40. Остальные узлы уходят без чтений, кроме этих двух полей. Все чтения памяти идут под SEH: при сбое снимок
   выбрасывается, взводится флажок «был сбой чтения», в лог он попадает один раз.
3. **Снимок фиксированного размера.** Структура без указателей на память игры, только числа:
   - узел, камера, `ctx`;
   - имя вида, до 31 символа, только печатные;
   - номер бита вида, маска `ctx+0x270`, флажки камеры `+0x18`, `+0x250`, `+0x8D0`, `+0x8E0`, карман `k`;
   - на каждый лист (до 7): маска листа `+0x30`, «пропускает» да/нет, 64-битная карта непустых карманов.
4. **Кольцо от потока игры к кадру EDVR.** Снимок кладётся в кольцо на 64 записи без блокировок. При переполнении
   запись теряется, счётчик потерь растёт — так же, как кольцо в `native_vr_probe_core.h`. В кадровой точке
   (`device_hook.cpp`, рядом с `tkNativeVrProbe`) зонд разбирает кольцо. Фильтр «только при смене» хранит последний
   снимок каждого узла; к снимку добавлен признак «на ногах» из журнала.
   - Отвергнуто: писать в лог прямо из хука. Это поток рендера игры, лог там тормозит.
5. **Чистое ядро отдельно.** `on_foot_hud_probe_core.h`:
   - разбор сырых полей в снимок, проверка «узел наш»;
   - фильтр смены, сводка раз в 30 с;
   - текст строк и проверка метки билда.

   Оно не трогает Windows и память игры, поэтому стенд гоняет его на подставных байтах. Хук, SEH и установка —
   в `on_foot_hud_probe.cpp`.
6. **Формат строк** (английский, как весь лог EDVR):
   - установка: `on-foot hud probe: hooked node draw at EliteDangerous64.exe+0x58F0F0, 16 bytes verified`;
   - отказ: `on-foot hud probe: NOT installed: <причина>`;
   - снимок узла:
     `on-foot hud probe: node 0x… view "PostGUIView_…" bit 1 lists 36-39 on-foot=yes cam 0x… flags 18=0x… 250=0x…
     masks 8d0=0x… 8e0=0x… ctx-mask=0x… pocket 3 | 36 pass=yes here=no elsewhere={0} | 37 …`;
   - сводка: `on-foot hud probe: 30 s: 90000 node draw(s) in all; PostGUI: 4 node(s), 7200 call(s), 3 line(s), …`.
     Первое число — все рисования узлов, которые видел хук. Если узлы PostGUI не приходят вовсе, это отличимо от
     «хук не работает».

   Строки начинаются с `on-foot hud probe:`, их легко выбрать из лога.
7. **Ключ.** `experimental.on_foot_hud_probe`, по умолчанию 0, `# dev: hidden`, live:
   - первое включение ставит перехват;
   - выключение только останавливает запись: хук остаётся и просто передаёт вызов;
   - снимается при перезапуске, как у `native_vr_probe`.
8. **Версия.** `v0.19.1-edvronfoot.11`.

## Risks / Trade-offs

- [`0x58F0F0` зовут из нескольких потоков] → кольцо многопишущее (атомарный индекс), фильтр живёт только в
  кадровом потоке.
- [Цена хука на узлах вне PostGUI] → два сравнения на вызов, без чтений сверх них. Узлов в кадре десятки, это
  незаметно.
- [Поля прочитаны неверно, и снимок врёт] → снимок содержит сырые значения: по ним видно, на что похожи числа.
  Строку имени вида проверяем на печатность. Если имя не читается, в строке `view "?"`.
- [В стерео узлы вида 1 вообще не вызываются] → это тоже ответ: в логе будут узлы только одного вида. Сводка
  покажет число узлов.
- [Карта карманов «есть» не говорит «сколько»] → для выбора следующего шага хватает «есть / нет»; счёт моделей — не
  цель.

## Migration Plan

- Сборка и установка обычным путём. Откат — ключ `on_foot_hud_probe = 0` (по умолчанию) или установка `.10`.
- После прогулки зонд остаётся в коде выключенным, пока не решим, нужен ли он ещё. Удаление — отдельной правкой
  вместе со следующей заявкой.
